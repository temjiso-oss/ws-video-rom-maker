# 仕様書: WS Video ROM Maker（動画 → ワンダースワンカラー ROM 変換アプリ）

## 目的
いろいろな形式の動画を、ワンダースワンカラー（WSC）/ スワンクリスタル（SC）の**実機**（フラッシュカート）で
再生できる `.wsc` ROM に変換する Windows 用アプリ。ユーザー向けの説明は `../README.md`。

## 映像方式
- 画面 224×144 = 28×18 = 504 タイル。カラー・4bpp・パックド（ポート 0x60 = 0xE0）。
- **ダブルバッファ**
  - A: タイル 0-503（0x4000〜）、マップ 0x1000、パレット 0-7（0xFE00〜）
  - B: タイル 512-1015（0x8000〜）、マップ 0x1800、パレット 8-15（0xFF00〜）
  - 隠れている側に書き、VBlank 割り込みでポート 0x07 を切り替える。パレットも2組に分けたので書き換え中のちらつきなし。
  - コマ f はバッファ f%2（動画ごとに 0 から数える）。プレイヤーは各動画の開始時に必ず A から書く。
- **色**: 1コマ 8パレット × (黒 + 15色)。色0は全パレット透明→背景色（パレット0の色0 = 黒）なので、黒は常に使える。
  タイルごとに最適なパレットを選ぶ。パレットセットは場面が変わって誤差が 25% 以上悪化し、作り直すと 20% 以上良くなるときだけ更新（最短6コマ間隔、シーンチェンジなら2コマ）。
  更新したコマはそのバッファの全タイルを書き換える。減色は重み付き RGB 距離 + 8×8 ベイヤーディザ（タイル内で固定模様なので時間方向にちらつかない）。
- **差分**: 表示中のタイル（2コマ前の内容）より候補の方が誤差 tau 以上良くなるタイルだけ書き換える。
  tau は「自動」なら ROM 容量に収まる最小値を二分探索（最小 6）。固定: 最高6 / 高20 / 標準60 / 低160。
- **1コマの書き換え上限**（エミュレーター計測、12kHz 音声あり）: K=2 → 160 タイル（実測で 200 まで間に合う）、K≥3 は上限なし（504 全部で間に合う）。K=1（75fps）は不可。
  パレット更新コマは上限を無視するため、K=2 では遅れることがある（遅れたコマの後は予定時刻に追いつく）。

## ストリーム形式（ROM の先頭バンクから）
1コマ:
```
u8 hdr           bit7: このバンクの残りは空き（次バンク先頭から続く） / bit0: パレットあり
[256 バイト]     パレットあり: 8パレット×16色×u16（0x0RGB、色0は0）
繰り返し（タイル番号 < 504 の間）:
  u8 skip, u8 count
  count × { u16 マップ値 [, 32 バイト or 1 バイト] }
```
- マップ値 = タイル番号 | (パレット(+8 if B)) << 9 | bank(B)<<13。**bit15 が立っていれば1色タイル**で、続く1バイト（ニブル2つとも同じ値）で 32 バイトを塗る。
- 1コマは 64KB バンクをまたがない（入りきらないときは 0x80 を置いて次のバンクへ）。各コマの後に必ず1バイト以上残す。
- 音声は全動画の映像の後ろに連続して置く（u8、中心 0x80、各動画の末尾に 2048 バイトの無音）。

## ROM 構成
- 64KB バンク × N（1/2/4/8/16MB）。最終バンクがプレイヤー（セグメント 0xF000）。
- 映像はポート C2（セグメント 0x2000）、音声はポート C3（0x3000）で読む。ポート C0 は触らない。
- バンク番号は ROM の末尾を 0xFF とする値（`(物理バンク - N) & 0xFF`）で書く。ミラーのないカートでも正しく動くように。
- プレイヤーの設定表（オフセット 0x10〜）: `'WSVP'`, K, R(音声ライン数, 0=なし), flags, 本数, 0x91値(シフト以外), 0x94値, スピーカーのシフト初期値, シフトの最小値。
  0x20〜: 動画表 8バイト×64本（映像バンク, 映像オフセット, 音声バンク, 音声オフセット, コマ数）。
- ヘッダー（最後の16バイト）: jmp far, カラー=1, ROMサイズコード（1MB=03, 2MB=04, 4MB=06, 8MB=08, 16MB=09）, flags=04, チェックサム。

## 音声
- チャンネル2のボイスモード（ポート 0x90 = 0x22）。サンプルを 0x89 に書く。0x94 = 0x05（左右100%）。
- 0x91 = 0x09 | シフト<<1（スピーカー・ヘッドホン有効）。**シフト0（100%）は実機の内蔵スピーカーで音割れする**（実機で確認。イヤホンは問題なし）。
  初期値はシフト1（50%）。設定表 +10 = 初期シフト、+11 = 上ボタンで上げられる上限（通常1）。本体の上下ボタンはこのシフトを変える。0x9E は 3 固定。
- HBlank タイマー（0xA4 = R、0xA2 = 0x03 自動リロード、割り込みベクタ base+7、0xB2 bit7）で R ライン毎に 1 サンプル。
  1ライン = 256 クロック → 12000/R Hz。VBlank（159ライン = 75.47Hz）と同じクロックなので映像と音声はずれない。
- ffmpeg の dynaudnorm で音量をそろえる（オプション）。

## 16パレット（241色）モード（2026-11-08 追加、標準）
- コマの先頭バイト bit1 = 16パレット: 続く 512 バイトを PALSTAGE（0xFC00）に置き、VBlank 割り込みで画面を切り替えた直後に
  0xFE00 へ写す（`pal_apply`。VBlank を先に受け付けて sti し、音声割り込みを待たせない。16 movsw x 16）。
  bit1 が 0 で bit0 = 1 なら古い 8パレット形式（書く側のバッファの半分へすぐ書く）。プレイヤーは両方読める。
- 16パレットのときマップ値のパレット番号は 0-15 そのまま（バッファ B でも +8 しない）。パレットセットは両バッファで共有で、
  切り替わったコマとその次のコマは全体書き直し（これまでどおり）。
- nileswan のヘッダーは最大 29 セクタ（0xC200-0xFBFF）。
- 効果: 同じデータ量で元の映像との誤差が約14%減（グラデーション・夕焼け・肌で効く）。変換は約4割遅くなる。
  `Settings(pal16=False)` / CLI `--pal8` / GUI「1コマの色数」で 8パレットにできる。

## タイルのコピー（2026-11-08 追加）
- 記録の種類（マップ値の上位ビット）: bit15=1 → 1色タイル（+1バイト）、bit14=1 → コピー（+2バイト: sx, sy）、どちらも 0 → 32バイト。
- コピー: 表示中のもう一方のバッファ（= 1つ前のコマ）の画面座標 (sx, sy) から 8x8 を写す。sx は偶数（2ドット = 1バイト単位）、
  sy は任意。8 の倍数でなければ隣・下のタイルにまたがって読む（`tile_copy`）。またがる元タイルが全部同じパレット番号で、
  両バッファのパレットセットが同じときだけ使える。パレット番号はマップ値に入れる。
- 効果: ダブルバッファでは変化を2回（A と B に）送る必要があり、2回目が 34 → 4 バイトになる。
  さらに画面全体の動き（位相相関の山を強い順に3つ、解析時に計算して保存）の分ずらしたコピーも試す。
  1コマずつ同じ絵が続くアニメ風の映像で約 37% 減、スクロールの多いゲーム映像で約 8% 減。
- 選び方: 各タイルで「そのまま」「新しく送る」「コピー（ずれ0・動き候補）」のうち 誤差 + λ×バイト数（λ = tau/34）が最小のもの。
- 展開時間の重み: フル 1.0、1色 0.6、ずれなしコピー 0.6、縦だけずれ 1.2、横ずれ 4.0（エミュレーターで全面パンを計測して決定）。
  1コマの上限 `MAX_UNITS` = {K2:160, K3:330, K4:600, K5:800, それ以上 160×K}、60Hz はライン数の比で増やす。
  nileswan 版（1.3.2）は、展開と microSD の読み込みが同じ CPU の時間を取り合うので、各タイルの重みに
  「そのバイト数 × `NILE_READ_UNIT`（0.02、見積もり）」を足し、上限は ×`NILE_UNIT_MARGIN`（0.95、一度に4セクタ読む遅れの分）から
  音声1コマ分の読み込みの重みを引いた値。1.3.3 で実機の速さ `NILE_HW_FACTOR` = 0.80 も掛け、余裕は 0.90 に（60Hz・K5 で約 701）。
  実機の測定（-DBENCH、変身シーン）: 読み込み 4096 セクタ 220 VBlank（エミュ 168）＝1バイト約 5.3 サイクル、
  展開 192 コマ 745 VBlank（エミュ 655）＝1単位 約 316 サイクル＝1コマ約 805 単位。
  経緯: 1.3.0（読み込みを見ない上限 1001）は激しい場面でコマ落ち。1.3.1 で展開の上限だけ ×0.85 にしたら、2色・4色が減って
  バイト数が増え、読み込みが追いつかず音飛び → 早回し（いずれも実機の変身シーン）。
- nileswan 版の読み込み待ち（ensure_video、1.3.2）: 再生中（STARTED≠0）に今のチャンクが未読なら音を止めて読み、読めたら
  NEXTT = TICK + K にして音を再開する（一時停止の再開と同じ）。以前は音を鳴らしたまま待ち、読めたあとに映像が遅れを取り戻そうと
  早回しになり、av_sync が音を飛ばしていた。テスト用に `-DSTALLTEST`（stream_step を 64 VBlank 中 4 回だけ動かす）がある。
- 実機の速さの測定用（`-DBENCH`、nileswan 版のみ）: 再生の代わりに nile.inc の `bench` を動かし、①最大 4096 セクタ読む VBlank 数
  ②読み込み済みのコマを待たずに展開する（音あり）コマ数と VBlank 数 ③ライン数・K を10進で表示して止まる。
  作り方: `python -c "import build_player as b; b.build('player_nile.bin',['NILE','BENCH'])"` → `tests/remake_nile_rom.py` → **`python build_player.py` で普通の版に戻す**。

## 色の少ないタイル（2026-11-10 追加、1.1.0）
- 記録: マップ値の bit15 と bit14 が両方 1 → 次の1バイトが種類。1 = 2色: 色バイト（上位=色0, 下位=色1）+ 8バイト（1行1バイト、bit7 が左、1=色1）、計12バイト。
  2 = 4色: 色バイト2つ（色0色1, 色2色3）+ 16バイト（1行2バイト、1ドット2ビット、上位が左）、計21バイト。マップ値はフラグを消して書く。
- 変換: 解析時に各タイルの2色・4色の近似（貪欲に4色を選ぶ compact_approx）と誤差を保存（'cx', 'ex'）。
- 選び方: 選択肢 そのまま/新しく/写す/2色/4色 から「誤差 + λ×バイト + ν×展開時間」が最小のもの。読み込み速度（バイト）と展開時間の予算を超えるときは λ・ν を二分探索で上げる（choose_options）。
- 展開時間の重み: 2色 1.45、4色 2.6（tests/measure_units.py: 1種類だけを N 枚ずつ送り、遅れが出始める N を K2・K3 で比べて決定）。

## microSD の並行読み込み（2026-11-10、1.1.0）
- 1セクタ = WREAD 145バイト（0xFE + 前半144）→ READ 370バイト（後半368 + CRC2）。後半の受信中に前半を写し、次のセクタの前半の受信中に後半を写す。
  後半は PEND に残し、次の read_lba か pipe_flush（stream_step の最後、別の LBA へ移るとき）で写す。並行するのは stream_step の中（PIPE=1）だけ。

## 変換の高速化（2026-11-08）
- 減色 `quant_all`: ディザを [t, b]・[p, SW・p] の4列の行列積にまとめ、誤差は選んだ色の値を拾うだけにした（結果は同一、1.8倍速）。
- ROM 版の容量合わせ: 画質パラメータの候補を別プロセスで同時に試す（1回 8候補 x 3回で絞る）。`Analysis.desc()/reopen()` で一時ファイルを開き直す。

## 60Hz モード（実験的）
- `Settings(hz60=True)` → 1画面 199 ライン（ポート0x16 = 198、60.3Hz）。0x16 は偶数にする（WSdev: SwanCrystal で奇数値は液晶に悪いとされる）。
  ポート0x17（バックポーチ＝垂直同期の位置、WSC のみ、既定155）は必ず 0x16 - 3 にする。IPS 化液晶と TV スワンはここから4ライン後を画面の始まりとみなすため、動かさないと画像が下にずれる（実機で確認）。
  .WSV の版: 2 = 199 ライン、1 = 200 ライン（最初の版）。音声はライン単位（12000/R Hz）なので変わらない。
- 通常版: 設定表 +14 (`cfg_vtot`)。nileswan 版: ヘッダーの版バイト bit7。プレイヤーは `set_vtotal` で `LINESW` も合わせ、
  音ズレ補正と時間表示の計算に使う。fps = 12000 / (ライン数 × K)。

## 読み込み速度の守り（2026-11-08、約18分で音が飛んだ件の対策）
- 原因（推定）: 速度制限の対象外だった「パレットが変わったコマ」（全体の書き直し）が多い場面で、平均が設定値を超えていた
  （ゲーム映像・160KB/秒の測定で 5秒窓 115%、20秒窓 110%）。読み込みが少しずつ遅れ、音声リングが空になり、
  プレイヤーが87秒前の古い音声を鳴らしていた。エミュレーターで 60Hz 20分の再生は（TICK の一周も含めて）同期・遅れなし。
- 変換側: `delta_pass` で、速度の余裕（バケツ）が全体書き直し2コマ分に足りないときはパレットの切り替えを最大2秒待ち、
  その間は今のパレットで減色し直す（`quant_all`）。速度の目標は設定値の 95%。→ 20秒窓 100%、5秒窓 104%。
- プレイヤー: 次の音声チャンクが読み込み済みでなければ無音で待つ（`AHOLD`）。音ズレ補正は読み込み済みのチャンクにだけ進める。
- 一時停止中、時間の下に「先読みできている映像チャンク数 / 音声チャンク数」を表示（`osd_buf`）。

## 音ズレ補正（av_sync）
- 音声割り込みで鳴らしたサンプル数を 32bit で数える（HBLCNT 下位 + SMPLHI 上位、鳴らし始めで 0、F0 = そのときのコマ番号）。
- 毎コマ、期待値 E = (FRAMEI − F0) × K × 159 ÷ R と比べ、3000 サンプル以上遅れていたら APTR（とバンク・ACI）を進めて合わせる。
  音声が先（映像の遅れ）の場合は何もしない（映像側の予定時刻の仕組みで追いつく）。
- 割り込みを長く止めないよう、再生中のコピーは REP を使わず命令を並べる。

## 画面（GUI）
- 「② 使い方を選ぶ」= プリセット（gui.py の PRESETS）: nile60（nileswan・60Hz・K=3・250KB/秒）、nile（nileswan・75Hz・K=4・250KB/秒）、rom（ROM・K=5）、custom。
  プリセットが決めるのは 形式・fps・60Hz・読み込み速度だけ。明るさ・音声・ディザ・プレビュー等の好みは保持。
- 詳細設定は折りたたみ。設定は %APPDATA%\WSVideoRomMaker\settings.json（state・前回の保存先フォルダ・詳細を開いていたか）。

## 本体の操作
START/A 一時停止、B 最初から（nileswan 版は一時停止中の B でメニューへ戻る: menu_return。libnile の nile_soft_reset と同じく、音・割り込み・タイマーを止め、CMD12、フラッシュに 0xAB（起こす）、0xE2=0xDD、0xB7=0、0x00=0 のあと、スタックに置いた out 0xC0,al / out 0xE4,ax / jmp far FFFF:0000（AX=0xFFFF）でカートの IPL0 へ飛ぶ）、X2/X4 次/前の動画、X1/X3 スピーカー音量（0x91 のシフト）。ボタンは VBlank 割り込みで読む。
最後の動画の後は最初に戻る。

## 変換の並列化
- 1本の動画を 150〜900 コマの区間に分け、`multiprocessing`（spawn）で区間ごとに解析（`encoder.analyse_parallel`）。
  区間ごとに ffmpeg を `-ss 開始 -frames:v 数` で起動し、結果の一時ファイルを順につなげる。区間の頭でパレットを作り直す。
- プロセス数は CPU数-1（最大16）。exe 版は `app.py` で `multiprocessing.freeze_support()`。
- 差分パス（容量合わせの二分探索を含む）は1プロセス。ROM版の残りの時間の大半はここ。
- 解析結果の再利用（`encoder.AnalysisCache`、GUI がアプリを閉じるまで保持）: 動画ファイル（パス・サイズ・更新時刻）、
  開始・長さ、fps、画面の合わせ方、明るさ・コントラスト・彩度、インターレース解除、ディザが同じなら解析をやり直さない。
  音声も同様（レート・音量そろえ・音量）。出力形式・画質・ROM サイズ・読み込み速度・スピーカー音量の変更は再解析不要。
- ROM 版は解析の前に `rom_fit_precheck`（音声 + 1コマ最低300バイト > 容量）で明らかに入らない長さを止める。

## nileswan 版（microSD から読みながら再生）
- 出力: `<名前>.wsc`（1MB、最終バンクに `player_nile.bin`）と `<8.3名>.WSV`（ROM名の英数字5文字 + MD5 3桁）。
  `.WSV` は microSD のルートに置く（8.3 の短い名前で探す）。プレイヤーの設定表 0x20〜0x2A にその名前。
- プレイヤー（`player.asm` を `-DNILE` で、追加部分は `src/player/nile.inc`）:
  1. `POW_CNT(0xE2)=0x00DD` でI/Oロック解除、`BANK_MASK(0xE4)` の bit9-11 を消してバンクマスク解除。
  2. TF カードを初期化し直す（ロック解除で電源が切れるため）。libnile と同じ順: CMD0 → CMD8 → ACMD41(HCS) → CMD58、
     失敗したら ACMD41(0) → CMD1（nileswan エミュレーターは ACMD41 に 0x05 を返し CMD1 で通る）→ CMD16。初期化は 384kHz、その後 24MHz。
  3. FAT32（MBR あり/なし）のルートから名前で探し、クラスタの連続区間表（最大1024区間、0x2000〜）を作る。
  4. `.WSV` のヘッダー（最大31セクタ）を内蔵RAM 0xC200 に読む。
  5. 再生: 待ち時間（コマの切り替え待ち・一時停止中）に最大4セクタずつ読む。CMD18 の連続読み出しを続け、LBA が飛ぶときだけ CMD12。
     受信バッファ（ROMバンク510）を ROM1（0x3000, ポートD4）で読み、セルフフラッシュモード（ポート0xCE=1）で
     0x10000 に出した PSRAM へコピー。映像リング = PSRAM バンク16〜111、音声リング = 112〜127。
  6. 映像はセグメント0x3000（ポートD4、16bit）、音声はセグメント0x2000（ポートC2）で読む（通常版と逆）。
     バンクは必ず16bitポートで書く（RX の 510 の上位ビットが残らないように）。
  7. 再生開始前に映像6チャンクと音声1チャンクを先読み（LOADING 表示）。B・左右ボタンで動画を変えると先読みし直す。
- `.WSV` の形式（チャンク = 64KB）: チャンク0 = ヘッダー（'WSVD', 版1, K, R, 本数, チャンク総数 u32, ヘッダーのセクタ数 u16,
  0x10〜 動画表 8バイト×64（開始チャンク u32, コマ数 u16）, 0x210〜 チャンク種類のビット 0=映像/1=音声）。
  チャンク1〜 = 各動画の映像ストリーム（通常版と同じ形式、動画の頭はチャンク境界）と音声を 64KB に切り、
  「必要になる時刻」順に並べたもの（映像チャンクは最初に始まるコマの時刻 - 1コマ分、音声は位置÷サンプル毎秒）。
- 読み込み速度の制限: 1コマの平均バイト数 = 速度/fps − 音声分、ため込み上限 = 先読み6チャンク分のトークンバケツ。
  超えるコマは改善の大きいタイルから入れる（パレット更新コマは制限しない）。
- エラー画面: 文字列 + CODE（理由）+ 段階（01〜07=カード初期化、10〜12=ファイル、20=読み込み）。

## ジャンプ (10秒 / 1分)
- 変換時、`keyframe_interval` = 10秒ぶんのコマ数（偶数、15fps で 152）ごとに、そのコマと次のコマ（バッファ A と B）を
  全体書き直し（パレット付き）にする。データ量は数%増。読み込み速度の制限の対象外。
- パレット7 の色14=黒・色15=白を固定（`OSD_PAL`）。時間表示に使う。
- 通常版: プレイヤーの設定表 +12 (`cfg_kf`) = 間隔、0x220〜 `seekidx`（動画ごとの最初の番号 u16×64）、
  0x8000〜 ジャンプ表 8バイト（映像バンク, 映像オフセット, 音声バンク, 音声オフセット, 予備）。
- nileswan 版: ヘッダー +0x0E = 間隔、動画表の +6 = その動画のジャンプ表のヘッダー内の位置。ジャンプ表 16バイト:
  読み始めるチャンク(u32), そこまでの映像/音声チャンク数, 映像チャンク番号とオフセット, 音声チャンク番号とオフセット。
  プレイヤーはリングを空にしてそのチャンクから読み、`VSKIP/ASKIP` より前の番号のチャンクは読み飛ばす。先読みは映像2チャンク。
- プレイヤー: Y2/Y4 = ±1区間、Y1/Y3 = ±6区間（今いる区間 = FRAMEI ÷ 間隔 から数える。0 未満は 0、終わりより先は無視）。
  一時停止中に Y を押すと再開してジャンプ。
- 時間表示: スクリーン2（マップ 0x0800、スタックは 0x0800 から下へ）。映像が使わないタイル 504-511 / 1016-1021 に
  0-9 : / 空白 透明 の文字（`osdfont.bin`）。ジャンプ後と再開後は約2秒、一時停止中は出しっぱなし。
  秒 = コマ × K × 53 / 4000。
- 一時停止中の操作の案内（1.3.1、`osd_guide` / `osd_guide_off`）: 時間の1行上（15行目）に「A:サイセイ B:メニュー」
  （ROM 版は「A:サイセイ」だけ）。文字のタイルの空きがないので、案内を出すマスの映像タイル（A・B の同じ番号）を借りて
  文字（`guidefont.bin`、build_player.py の KANA）を書き、スクリーン2 の不透明なマスで覆う。元のタイルは MAP2 の見えない
  18行目以降（0x0C80〜、1文字 64 バイト）に退避し、再開時（次のコマを展開する前）に戻す。
- 古いファイル（間隔 0）はジャンプしない（一時停止中の時間表示の色は不定）。

## 確認方法
- `python tests/verify.py rom.wsc [フレーム数]`: エミュレーターの画面と、ROM を Python で読み戻した画面（sim_rom.py）が一致するか。
- `python tests/run_rom.py rom.wsc 出力 [フレーム数]`: 画面の PNG と音声 wav を書き出す。
- `python tests/measure_budget.py 動画 作業フォルダ [K,...]`: 1コマのタイル上限ごとに遅れを数える。
- `python tests/seek_test.py rom.wsc`: 通常版でジャンプを繰り返し、画面が順に読み戻した画面と一致するか（時間表示の場所は除く）。
  libretro の入力ID: Y1=13, Y2=11, Y3=12, Y4=10。nileswan エミュレーターでは Y = 矢印キー。
- nileswan 版: `tools/nileswan-emu/`（公式の nileswan-medem と IPL0・SPI・512MB の FAT32 SD イメージ）。
  1. `python tests/fat32img.py nileswan.img put X.WSV X.WSV [--fragment N]`（N クラスタごとに隙間を空けて断片化）
  2. `python tests/fat32img.py nileswan.img put player.wsc NILESWAN/MENU.WS`（プレイヤーをメニューとして起動させる）
  3. `python tests/run_nile_emu.py nileswan.ipl0 出力 3,6,10 [--keys 44:RIGHT]`（Mednafen の F9 で画面を保存。デスクトップは撮らない）
  - ROM を直接起動すると nileswan のハードがつながらない（SPI が busy のまま）。必ず IPL0 から。
  - `player_nile.bin` だけ作り直したときは `tests/remake_nile_rom.py`。

## 保存先の名前と、1本ずつの変換（2026-11-22、1.1.1〜1.2.0）
- 保存先の名前は、いちばん上の動画の名前から自動で付ける。空のとき、または前に自動で付けた名前のままのときだけ付け直す（自分で決めた名前は変えない）。理由：.WSV の名前は ROM の名前から決まるので、同じ ROM 名で別の動画を変換すると .WSV が上書きになる。
- 「1本ずつ別の ROM にする」（初めは切、保存しない）：動画が2本以上のとき、保存先と同じフォルダーに「動画の名前.wsc」を1本ずつ作る。名前や .WSV の名前が重なるときは _2 などを足す（gui.split_outputs）。切のときは、今まで通り全部を1つの ROM にまとめる。
